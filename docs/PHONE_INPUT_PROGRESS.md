# Phone display and input experiment — 2026-11-03

The debug host now configures the SDL viewport using the Android maximum window bounds in landscape and selects a 1x–3x GUI scale in quarter steps while keeping at least a 640x360 logical menu area. This runs on each launch and overrides the game viewport and GUI scale settings; it does not scale down the Android surface. Insets, display cutouts, dynamic resolution changes and physical phones still need validation. The user can change the GUI scale in-game, but the next launch currently resets it.

On the 2400x1080 ARM-translated emulator, the engine reported both a 2400x1080 SDL window and a 2400x1080 OpenGL framebuffer. Previously the framebuffer was 1024x768 even though the surface was 2400x1080, and the menu was clipped. The 3x GUI scale enlarged menu geometry but did not enlarge text until the matching v469e `Textures/UWindowFonts.utx` was staged. `prepare_private_content.py` now selects that package from the hash-verified patch archive instead of the older user installation. With it, the menu text visibly grew and the earlier missing Tahoma40 warning disappeared. The screenshot is in ignored `research/menu-font-469e.png`. Phone readability and all other menu screens remain unverified.

The debug SDL Java patch no longer treats a DPAD-only keyboard as a gamepad, and the host disables SDL's accelerometer-as-joystick device. The emulator then logged `Detected 0 joysticks` where it had previously selected its `qwerty2` keyboard. Version 0.8 enables joystick input and initializes a controller mapping once, preserving a backup of the original private User.ini and leaving later edits in place. Right-stick axes are mapped to JoyZ/JoyR; trigger thresholds synthesize Insert/PageUp, whose default bindings are alternate fire/fire. Start remains Escape. Android joystick axis ordering differs across controllers, and physical-phone input and hot-plugging are unverified.

The SDL surface now translates a touchscreen tap into a pointer move followed by a delayed mouse press and release. On the 2400x1080 emulator, one tap on Start Practice Session opened its setup and one tap on Start loaded the default DeathMatch map. Switching directly between top-level menus while a dropdown is already open can still take two taps: the first closes the existing dropdown. Touch events are not yet restricted to menus, so they may still trigger the original game's mouse bindings during gameplay. Physical-phone touch and gameplay remain unverified.

The bottom-right overlay opens the Android keyboard. SDL's virtual-key event ordering was adapted so ASCII text arrives between key-down and key-up, as required by UT99's edit boxes. On the emulator, typing `Codex` replaced the selected player name and the keyboard backspace removed its last character. Non-ASCII input, other IMEs, autocomplete edge cases, and physical-phone behavior need further validation. The current bootstrap applies the recorded SDL patch before rebuilding SDL and the private runtime bundle.

The debug APK includes the experimental runtime but requires the user's separately supplied game content in shared storage. No sound was verified in this experiment. This remains a research build, not a completed game port.

The debug activity maps Android gamepad `BUTTON_START` down/up events to Escape and consumes the original Start event. An injected `input gamepad keyevent BUTTON_START` opened the original menu from the intro in the emulator. A physical controller, different vendors' mappings, and in-game pause/resume remain unverified.

Phone follow-up: the user reports Start toggles between the metal UT background with no top menu and a black UT screen. This was not reproduced with an injected Start on the emulator at 2400x1080 or 3200x1440; at both sizes the original menu bar appeared. Version 0.5 adds a per-launch input diagnostic to manual/crash reports: maximum window bounds, SDL surface dimensions, requested SDL viewport and GUI scale, and Start/Escape key events and source flags. It does not yet measure the actual OpenGL framebuffer or establish the phone's root cause. Emulator testing confirmed that a manual report after reopening the app contains the diagnostic.

The phone's v0.5 report shows matching 2608x1200 requested viewport and surface, plus repeated `UMenuMenuBar` and `UMenuStatusBar` warnings that `LookAndFeel` is None. Its log tail omits the original style-load failure, so the exact cause is unknown. On the emulator, setting `LookAndFeelClass` to a nonexistent class reproduced the missing bar and the same warnings. Version 0.6 sets the stock `UMenu.UMenuBlueLookAndFeel` before launch, replacing any existing menu-style choice. With the invalid style seeded, the rebuilt APK restored the visible menu, and a single tap opened practice setup. The change needs verification on the physical phone. Swapping the emulator's menu packages to an older GOTY copy did not reproduce the missing bar; the v469e packages were restored afterward.

Version 0.7 maps both lowercase and uppercase M from the Android soft keyboard to Escape. This applies while entering text too, so M cannot currently be typed through that keyboard. On the emulator, tapping the Gboard M key during the intro opened the menu, repeated taps continued to trigger Escape, and `Alex` was entered in the player-name field. Different keyboard apps, composition behavior, and the physical phone remain unverified. Controller Start retains its existing Escape mapping.

Version 0.8: Android Back opens a confirmation, with keyboard Back first dismissing the keyboard; emulator checks covered cancelable confirmation and Exit returning to setup. An Android uinput Xbox-style Bluetooth fixture exposed eight axes, which made the original driver's six-entry mapping assert. The SDL Java joystick enumeration is now limited to six axes. With the fixture attached before launch, UT99 logged one joystick with six axes and booted; virtual B and Select did not close its open menu, and both virtual trigger press/release transitions were captured in the host. Physical sticks, triggers, gameplay, multiple devices and controller hot-plugging remain unverified. UT's Controls screen did not reliably capture the virtual controller button during a rebinding attempt, and touch selection could bind Left Mouse, so in-game controller customization remains unfinished.

Practice setup still shows an empty Game Type selector. Directory tracing confirmed the shared System directory was opened and Botpack.int could be read, but registry discovery remains unresolved. Emulator comparisons using older Botpack.int and a separate localization directory did not fix it. Adding `System/*.int` as an engine package search path caused a startup error and was removed. The user's game assets were not changed by these tests; temporary emulator copies were restored or removed.

Version 0.9 is an unfinished controller experiment. SDL opens the emulator's virtual Xbox controller as a joystick, and diagnostic logs show Start and the right trigger entering the opened joystick as buttons 6 and 16. Trigger events no longer synthesize keyboard keys, and repeated Android key-down events are suppressed. A short Start press reached SDL during the intro but did not visibly skip it in the last test, so this build is not yet verified as a replacement for 0.8. In-game rebinding, physical Xbox input, and the empty game-type selector remain unresolved. A temporary localization-path symlink experiment was removed from the source and the emulator; it did not yield a conclusive game-mode result.

Version 0.10: a temporary diagnostic showed 161 localization files discovered, followed by a failed `FConfigCache` to `FConfigCacheIni` dynamic cast even though the actual object had the latter type. The NDK C++ ABI bridge now contains a narrow exact-type compatibility fallback; the host redirects the pinned 469e Core import to that bridge because Android's process-global C++ runtime otherwise wins symbol resolution. The import offset is specific to the catalog-pinned Core binary. The host preserves the original memory-page protections. The final build displayed the stock game-type list, selected AS-Frigate when Assault was chosen, and started a match showing a red team HUD and countdown. An earlier diagnostic build also showed a blue opponent; objective completion and turret targeting were not verified. Physical-device operation and other C++ ABI compatibility remain unverified.

The virtual Xbox fixture was detected as an SDL joystick and its B button reached an opened SDL joystick as button 1, but pressing it in the original Controls screen did not produce a visible rebind. The Android test fixture's trigger axes were identified as generic axes, so that fixture did not validate actual trigger gameplay. Real Bluetooth controller axes, trigger mapping, rebinding and hot-plugging remain open. The old fresh-install PageUp/Insert trigger defaults have been removed; the engine's right trigger button is currently displayed as `Unknown D8`, not a controller-friendly label. An unrelated temporary SDL-driver trace crashed the emulator and was removed.

Version 0.11 corrects two controller issues. UT logged that it clamps joystick buttons to 16, so the previous button 17 for R2 could never work. L2 now uses joystick button 6 (the former Guide slot), R2 uses joystick button 16, and the Guide key is not sent to gameplay. Untouched prior default trigger bindings migrate to these slots; modified bindings are preserved. Joystick motion now goes directly from Android to SDL instead of depending on view focus, and gamepad keys do not fall through to keyboard handling. The on-device diagnostic records controller identity, axis ranges, sampled motion, and button events.

The earlier unsuccessful rebind test injected a press and release only 7 ms apart. With a sustained virtual B press, UT captured and saved `Joy2=Fire`; the same binding started an Assault match. The emulator registered 16 buttons and four axes and responded to held left- and right-stick axes during gameplay. The final no-trace APK booted and registered the fixture. The fixture reported trigger keycodes as unknown, so actual trigger operation is unverified; a physical Bluetooth controller, its axis layout and connection changes remain unverified. A controller should be connected before launching UT because the engine opens its joystick during startup.

Version 0.12 fixes a controller-selection failure confirmed by the user's Xiaomi report: Android delivered Xbox buttons and motion, but UT opened the zero-axis `uinput-xiaomi` as joystick 0 and SDL reported the Xbox as registered but unopened. SDL's Android device enumeration now prioritizes controllers with left-stick axes and joystick sources before digital-only gamepad devices; digital-only devices remain available as fallback. In an emulator with an earlier-registered zero-axis gamepad and a later Xbox-style joystick, SDL logged the latter as opened and the former as unopened, and the selected joystick's left stick moved the player during a practice match. The exact phone and physical Bluetooth controller still need confirmation, and connecting or replacing controllers after the engine opens its first joystick remains unverified.

Version 0.13 uses the user's confirmed axis scaling as new-install defaults, reverses JoyY, and migrates only the exact previously recommended positive 300 JoyY binding, backing up the prior file. Other existing bindings are retained. The user's physical controller still needs to verify this migration. A live camera sensitivity slider and the reported incorrect joystick dodge directions remain unfinished.

The debug APK now requests INTERNET. A listen-server test previously crashed in IpDrv's InitBase when it treated Android's addrinfo as the GNU layout. The versioned libc bridge now converts its swapped address and canonical-name fields, common hint flags, and resolver error numbers. With that bridge, an emulator listen server loaded DM-Agony, bound UDP 7777 and 7778, and answered a local UDP status query with its map and player information. This is not a client join, LAN discovery, internet server-list, or phone test; those remain open. The bridge does not establish general Linux networking ABI compatibility.

Version 0.16 adds a live camera-sensitivity slider through the in-game gear button. It multiplies JoyZ/JoyR axis input and retains the existing `User.ini` bindings. In an ARM-translated Android emulator, a connected virtual four-axis joystick produced input 0.305 and output 0.711 at 233%; changing the slider to 100% while held produced output 0.305. The 233% value survived a game-process relaunch. This is input-boundary evidence, not a physical-controller or camera feel test. Dodge direction remains unresolved. See `MODLOG.md` for the pinned-driver hook and limitations.

Version 0.17 applies the requested Xbox layout once with a private `User.ini` backup, then preserves later custom remaps. It adds a 10% per-axis stick dead zone, leaving the trigger axes unfiltered. A native math fixture passed, and a virtual joystick's right-stick input reached the game with the expected reduced magnitude. Start sends the same Escape UI event in addition to its joystick event, with Joy7 unbound by default; in the emulator it opened the original menu, and Select showed the scoreboard. LT/RT, LB/RB, A and right-stick translocator gameplay still need device verification. Left-stick click is reserved but does not yet perform the requested directional dodge; the earlier double-flick direction issue remains unresolved.
